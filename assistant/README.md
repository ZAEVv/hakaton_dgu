# Сервис заявок колледжа

[Карта проекта для ИИ-агента](../PROJECT_MAP.md)

Запуск из папки проекта:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r assistant/requirements.txt
cp assistant/.env.example assistant/.env
# Задайте SECRET_KEY в assistant/.env: выведите и вставьте результат этой команды
python -c 'import secrets; print(secrets.token_urlsafe(48))'
# Для локального HTTP установите в assistant/.env SESSION_COOKIE_SECURE=0
python assistant/seed.py
python assistant/main.py
```

Если `.env` уже существует, не перезаписывайте его командой `cp`.

Откройте http://127.0.0.1:5000. Сначала создайте аккаунт заявителя: имя, фамилия, логин (студент может использовать номер зачётной книжки) и пароль с подтверждением. Затем войдите по логину и паролю. Форма принимает помещение, категорию, описание и необязательное фото JPEG, PNG или WebP размером до 4 МБ. Создание заявки записывается в историю. Все заявки, их статусы, публичная переписка и фотографии доступны владельцу в личном кабинете `/account`. Панель сотрудника доступна отдельно по `/login`.

## Аккаунты заявителей

- `/account/register` — регистрация: имя и фамилия до 80 символов каждое, логин до 40 букв (латиница/кириллица), цифр, дефисов или `/`, пароль от 10 до 256 символов. Логин уникален; пробелы по краям убираются, регистр букв не учитывается. Пароли хранятся только в виде хешей Werkzeug.
- `/account/login` — вход по логину и паролю. Имя и фамилия указываются при регистрации, но не заменяют пароль. Регистрация самостоятельная: система пока не проверяет данные по реестру колледжа и не подтверждает личность заявителя.
- `/account` — личность владельца и только его заявки с текущими статусами. `/` — отправка новой заявки после входа. `/account/tickets/<id>` — карточка своей заявки и публичная переписка. Владелец не может менять статус, исполнителя или автора заявки через поля формы.
- Фото по `/account/attachments/<id>` доступны только владельцу заявки после проверки сессии и принадлежности файла заявке. Чужие/несуществующие заявки и фото возвращают одинаковый HTTP 404. Сотрудники продолжают видеть все фотографии через свой защищённый маршрут.
- Сессии заявителей проверяются в базе на каждом запросе и действуют не более 12 часов. `/account/logout` — POST с CSRF, который отзывает сессию на сервере, включая скопированную cookie. Вход в аккаунт сотрудника в том же браузере завершает текущую сессию заявителя, и наоборот; для одновременной проверки используйте разные профили браузера/режим инкогнито.
- Сотрудники видят имя, фамилию и логин в списке, карточке и профиле заявителя `/admin/applicants/<id>`. Поиск работает и по фамилии или логину. Пароли и их хеши нигде не показываются.
- **Секретные ссылки больше не дают доступ:** старый маршрут `/ticket/<token>` возвращает HTTP 410 для GET и POST. Старые заявки без владельца не привязываются к новым аккаунтам автоматически и видны только сотрудникам. Данные сохраняются; перед миграцией сделайте резервную копию базы. Восстановление пароля заявителя и подтверждённый перенос старых заявок в этой версии не реализованы.

## Форма заявки (MVP)

- Адаптивная форма с отдельным ручным выбором корпуса и помещения. JavaScript показывает помещения выбранного корпуса; без JavaScript доступны все помещения, а сервер проверяет их принадлежность корпусу.
- Корпус, помещение, категория и описание (до 5000 символов, не только пробелы) обязательны. Неверные значения сервер не сохраняет.
- **Фотографии включены в MVP.** Сервер проверяет фактический формат и декодирование JPEG/PNG/WebP, размер до 4 МБ и разрешение до 20 мегапикселей. Имя и MIME-тип от браузера не считаются доказательством формата. Файл сохраняется под случайным именем вне каталога статических файлов. Максимальный размер всего запроса — 5 МБ; оригиналы HEIC с телефона нужно преобразовать в JPEG.
- При отправке кнопка блокируется. UUID v4 запроса и уникальное ограничение в базе предотвращают повторное создание, включая одновременные запросы. Повторная отправка с тем же ключом открывает ту же заявку. Без JavaScript защита на сервере продолжает работать.
- Номер (`tickets.id`) появляется только после успешной фиксации транзакции. Заявка сохраняется за текущим аккаунтом; подставить чужого владельца через форму нельзя. Повторная отправка с тем же ключом возвращает свою заявку, но не раскрывает чужую. Страницы не кешируются, Referer не передаётся другим сайтам.
- При сбое записи возвращается ошибка (HTTP 503), транзакция откатывается, созданный файл удаляется. При ошибке полей или фото возвращается HTTP 400, при превышении общего размера — 413. Обычная ошибка сохраняет введённый текст и ключ запроса, но фото нужно выбрать заново; после 413 нужно вернуться к форме.

## Настройки и секреты

Приложение загружает `assistant/.env`. Переменные окружения имеют приоритет. `DATABASE` и `UPLOAD_DIR` задают пути к базе и фотографиям; относительные пути считаются от `assistant/`. Для помощника используется `DEEPSEEK_API_KEY`; поле `API_KEY` не используется для подключения DeepSeek. `.env.example` не содержит реальных секретов.

`SECRET_KEY` обязателен для форм и панели: без него они возвращают 503. Используйте постоянный случайный ключ, храните его только в защищённом `.env` или переменных окружения, не в Git; замена ключа завершает все сессии. Cookie имеют HttpOnly и SameSite=Lax, по умолчанию Secure; отключать Secure можно только в локальной разработке без HTTPS. За пределами локальной разработки используйте HTTPS, production WSGI-сервер, ограничение попыток входа на прокси и ограниченный доступ к файлам базы/вложений. В приложении также действует ограничение попыток входа.

## Панель сотрудника

После входа доступны список и поиск по номеру, описанию, помещению, фамилии и логину (без учёта регистра, включая кириллицу), фильтры по статусу, категории, корпусу, конкретному помещению и исполнителю, а также по дате создания с/по (UTC, обе границы включены). Фильтры можно сочетать. Помещения с одинаковым названием в разных корпусах различаются по идентификатору.

Роли:

- **Администратор** видит и обрабатывает все заявки, назначает активных сотрудников, в том числе себя. На странице `/admin/employees` создаёт исполнителей, блокирует/разблокирует их и сбрасывает пароли. Публичной регистрации нет. Новые пароли — от 10 до 256 символов, хранятся только как хеши.
- **Исполнитель** видит все заявки, историю и фотографии, но меняет статус и оставляет комментарии только в назначенных ему заявках. Может взять свободную незакрытую заявку себе, но не может снимать или менять назначение.

При блокировке все сессии сотрудника отзываются, назначения его незакрытых заявок снимаются; история и назначения закрытых заявок сохраняются. Разблокировка не восстанавливает старые сессии или назначения. Сброс пароля тоже завершает все сессии. Управление сотрудниками записывается в отдельную историю с автором и временем UTC; пароли в историю не попадают. Себя заблокировать нельзя.

Первого администратора без демонстрационных данных можно создать из корня проекта:

```bash
.venv/bin/flask --app assistant/main create-admin
```

Команда спросит логин, имя и пароль с подтверждением (скрытый ввод). Пароль не нужно передавать аргументом командной строки. После этого откройте `/login`. Для запуска приложения без демо-данных помещения нужно предварительно добавить в таблицу `rooms`.

Карточка поддерживает семь статусов: «Новая», «На рассмотрении», «Назначен исполнитель», «В работе», «Нужны уточнения», «Решена», «Отклонена». Строгой последовательности переходов нет. Администратор и назначенный исполнитель могут повторно открыть закрытую заявку. При переходе в «Решена» обязателен публичный итоговый комментарий, при переходе в «Отклонена» — публичная причина. Внутренняя заметка не заменяет итог. Старый статус «Закрыта» показывается как «Решена» и при инициализации базы мигрируется в него без изменения записей истории.

Заявитель из своего аккаунта может добавлять публичные ответы до решения/отклонения заявки. Ответ сохраняется в истории с идентификатором заявителя и не меняет статус; статус меняет сотрудник. Ответы ограничены 5000 символами, защищены CSRF и инвалидируют открытые сотрудниками старые версии карточки. Внутренние заметки заявителю не видны.

Перед обновлением базы создайте резервную копию. Миграция добавляет роль и активность без удаления данных: **все существовавшие сотрудники сохраняют права администратора**, поскольку ранее они имели полный доступ. Проверьте существующие учётные записи перед публикацией; при необходимости заблокируйте ненужные. Новые сотрудники из панели получают только роль исполнителя.

При сохранении проверяется версия карточки: если другой сотрудник уже изменил её или добавил комментарий, возвращается HTTP 409 без перезаписи заявки и истории. Обновите страницу, сверьте изменения и повторите ввод. История содержит автора и время UTC. Вложения выдаются вошедшим сотрудникам или владельцу заявки после серверной проверки доступа. Все формы защищены CSRF. Сессия сотрудника действует не более 12 часов и отзывается на сервере при выходе; удаление сотрудника также лишает доступа.

`TRUSTED_HOSTS` — список разрешённых доменов/IP через запятую, без схемы и порта. По умолчанию разрешены только `localhost`, `127.0.0.1`, `[::1]`: неизвестные значения Host отклоняются. Для проверки на телефоне добавьте локальный IP компьютера в `.env` и после подготовки базы запустите `.venv/bin/flask --app assistant/main run --host=0.0.0.0`. Открывайте адрес компьютера с телефона в той же сети. Встроенный сервер предназначен только для разработки; публичное размещение требует production WSGI-сервера и HTTPS.

`.env`, старый `api.env`, SQLite-файлы, фотографии, виртуальное окружение и Python-кеш исключены из Git. Если ключ раньше был опубликован, удаление файла из отслеживания не удалит его из истории: отзовите ключ у провайдера и создайте новый.

## База и демонстрационные данные

`schema.sql` содержит помещения, сотрудников и заявителей с хешами паролей, серверные сессии, заявки (номер — `id`) с владельцем, историю, вложения и базу знаний. Таблица `ticket_access` сохранена для старых данных и внутренней идемпотентности `request_key`; её токены больше не авторизуют доступ и не показываются пользователям. `python assistant/main.py` создаёт недостающие таблицы и обновляет старую базу без удаления данных.

`python assistant/seed.py` добавляет демонстрационные помещения, администратора `demo`, три заявки с разными статусами, публичные и внутренние записи истории и два примера ответов базы знаний. Повторный запуск не дублирует эти данные, не сбрасывает пароль и не меняет роль существующего `demo`. Вложения появляются при загрузке фотографии через форму.

При первом создании сотрудника скрипт выводит случайный пароль один раз; сохраните его. Можно предварительно задать `DEMO_PASSWORD` в `.env`. Пароль хранится в базе только как хеш. Для входа используйте логин `demo` и выданный пароль.

У ответов базы знаний есть признак `is_verified`. Примеры не выдаются за официальные сведения колледжа и имеют значение `0`. Перед публикацией ответов ответственный сотрудник должен проверить их содержание и установить `is_verified = 1`.

## QR-коды, ИИ и статистика

Администратор открывает `/admin/qr` и создаёт или скачивает QR-коды мест. Откройте панель по адресу сервера, доступному телефону: этот адрес попадёт в QR-коды. Если адрес сервера изменится, коды надо создать заново. Демонстрационные места добавляет `seed.py`.

Для DeepSeek задайте `DEEPSEEK_API_KEY` в `assistant/.env`. По умолчанию используется `deepseek-flash`; модель можно изменить в `DEEPSEEK_MODEL`. Запросы отправляются через сервер, фотографии и данные аккаунта не добавляются автоматически, но текст, введённый пользователем, передаётся провайдеру. ИИ предлагает категорию и краткое описание; чат отправляет заявку после выбора места. ИИ не закрывает заявки. В случае ошибки доступна обычная форма. Ограничение: до 10 запросов в минуту и 60 в час на аккаунт, не более 300 в час на весь сервер; предупреждение по опасным словам работает отдельно и не охватывает все формулировки.

Проверенные ответы читаются из `knowledge_base` с `is_verified=1`. Для демонстрации можно явно включить `DEEPSEEK_DEMO_KNOWLEDGE=1`: ответы будут помечены как примеры и требуют проверки колледжем. Без ключа API классификация не работает; предупреждение для распознанных опасных сообщений остаётся доступным.

Панель показывает общее число заявок, открытые и решённые. Открыты все, кроме «Решена», «Закрыта» и «Отклонена». Значения не зависят от фильтров.

Для применения новых таблиц к существующей базе сначала создайте резервную копию SQLite и папки фотографий. `python assistant/main.py` и `python assistant/seed.py` запускают инициализацию, а `flask run` — нет.

Входы ограничены 15 попытками за 10 минут с одного IP для каждой формы. Если сервер находится за обратным прокси, без доверенной настройки адресов это ограничение может применяться ко всем пользователям прокси сразу. Для доступа через Интернет требуется HTTPS и корректная настройка прокси.

Регистрация ограничена 15 попытками за 10 минут с одного IP. При загрузке новые фотографии пересохраняются без исходных метаданных. Это не меняет ранее сохранённые фотографии.

## Чат заявителя

На странице подачи заявки помощник уточняет проблему. После распознавания неисправности и выбора места (или при наличии места из QR-кода) чат автоматически отправляет заявку. Ручная форма и загрузка фото доступны ниже. Во время отправки повторная отправка блокируется, а сервер проверяет уникальный ключ. Если ИИ недоступен, можно воспользоваться ручной формой. Переписка с ИИ до создания заявки сохраняется только в текущей вкладке браузера; после создания публичные комментарии сотрудника и ответы заявителя доступны в карточке заявки.

В карточке сотрудник может нажать «Принять в работу и сообщить заявителю»: это устанавливает статус «В работе» и публикует стандартный ответ. Статус и сообщения видны владельцу заявки в личном кабинете.

ИИ готовит краткое описание проблемы по переписке, а место хранится в отдельном поле. Модель может ошибаться, поэтому неоднозначные сведения стоит уточнять у заявителя. Для опасных сообщений сначала показывается предупреждение; если при отправке ИИ недоступен, сохраняется исходное сообщение о проблеме.
