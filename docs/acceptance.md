# Соответствие критериям приёмки

| Критерий | Реализация | Проверка |
| --- | --- | --- |
| AT-01 Кабинет по QR | /chat?qr=... и проверка случайного qr_key | pytest QR + Playwright кабинет 214 |
| AT-02 Создание и номер | POST /api/tickets, SQLite, номер УПК-00001 | API + E2E с фото |
| AT-03 Панель сотрудника | /admin/tickets | E2E |
| AT-04 Поиск и фильтры | Текст, статус, категория, кабинет, даты | API фильтрация + UI |
| AT-05 Исполнитель, статус, комментарий | PATCH с проверкой роли и версии | API + E2E |
| AT-06 Безопасное отслеживание | 256-битный token, хеш в БД | API изоляция + E2E |
| AT-07 Типовой вопрос | 8 инструкций, источник, DeepSeek JSON | Параметризованные сценарии + mock DeepSeek |
| AT-08 Неисправность | Карточка заявки в чате с явным подтверждением | API + E2E |
| AT-09 Опасность | Серверное правило до модели, срочный приоритет | Искрение и самостоятельная замена проводки |
| AT-10 Неизвестный запрос | Честный ответ о нехватке сведений | API неизвестный вопрос |
| AT-11 Защищённая панель | HttpOnly-сессия, серверная RBAC | 401 без входа, 403 для staff |
| AT-12 История | Автор, время, старый/новый статус, события | API + E2E решение |

Дополнительно проверены повторная отправка без дубликата, подмена содержимого idempotency-key, некорректный кабинет, запрещённый Origin, скрытие внутренних заметок, фото чужой заявки, повреждённое изображение, ZIP с 43 PNG, перевыпуск QR, создание сотрудников и категории, некорректный адрес, сбой/пустой ответ DeepSeek.

Браузерные проверки охватывают 1440, 1024, 820, 768 и 390 пикселей, две палитры, reduced motion. Живые запросы DeepSeek остаются отдельной проверкой после добавления ключа. Тестовый HTTP-сервис не подтверждает качество реальной модели, но проверяет протокол интеграции и резервное поведение.
