# Цифровой помощник УПК

Рабочее веб-приложение по ТЗ «УПК: Цифровой помощник колледжа». Студент сканирует QR кабинета, общается с помощником, подтверждает заявку и следит за ней по безопасной ссылке. Сотрудник обрабатывает обращение в отдельной панели. Бэкенд написан на **Python (FastAPI)**, фронтенд — **React**, база — **SQLite**.

## Запуск

Нужны Python 3.11+ и Node.js 22.12+. Из каталога проекта:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
npm ci
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173. Панель сотрудников — http://localhost:5173/admin. При первом запуске система создаёт пользователей `admin` и `staff` со случайными паролями. Они записаны в `.local-credentials` с правами 600. Файл исключён из Git. Также можно задать `ADMIN_PASSWORD` и `STAFF_PASSWORD` в `.env` **перед созданием базы**. Впоследствии пароли и доступ меняются администратором в разделе «Сотрудники».

В подготовленной рабочей папке зависимости уже установлены. Для повторного запуска достаточно `npm run dev`.

## DeepSeek

1. Запишите ключ в серверный `.env`: `DEEPSEEK_API_KEY=...`.
2. При необходимости измените `DEEPSEEK_MODEL` (по умолчанию `deepseek-flash`).
3. Перезапустите сервер. Интерфейс покажет подключённый режим.

API-ключ не попадает в JS-сборку, API-ответы и репозиторий. Системный промпт хранится в `settings` базы, редактируется администратором в «Настройки → Системный промпт» и применяется к новым ответам помощника. Сервер передаёт модели проверенное место, базу знаний и до восьми сообщений диалога. Фото остаются в системе заявок и не передаются модели.

Интеграция использует [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) и [структурированный JSON](https://api-docs.deepseek.com/guides/json_mode/). Формат и поля ответа проверяются. Пустой/повреждённый ответ, таймаут или ошибка API включают явно обозначенный резервный режим. Пока ключа нет, доступны детерминированная классификация и восемь локальных инструкций — это **не вызовы внешней ИИ-модели**.

Опасные сообщения обрабатываются отдельным серверным правилом до обращения к модели. Информационные ответы выдаются из подтверждённого источника базы знаний. Помощник никогда не регистрирует и не закрывает заявку сам. Тексты пользователей и история не имеют прав изменять системный промпт. Консервативные проверки снижают риски, но не заменяют проверку сотрудником.

## Телефон и QR-коды

Подключите телефон и компьютер к одной сети. В админке откройте «Настройки» и укажите доступный с телефона адрес приложения, например `http://192.168.1.253:5173`. Изменение адреса влияет на новые изображения QR — старые нужно скачать и распечатать заново. Vite и FastAPI слушают `0.0.0.0`; при необходимости разрешите входящие подключения в настройках сети/VPN/межсетевого экрана.

«Кабинеты и QR-коды» показывает все коды как PNG, позволяет скачать один PNG или ZIP целиком, редактировать кабинет и перевыпускать QR-привязку. После перевыпуска старый QR перестаёт определять кабинет, система предлагает ручной выбор. Отключённые кабинеты не принимают новые заявки. Изменение кабинета у существующей QR-привязки меняет место, на которое она указывает.

Подготовлены ровно 43 кабинета:

- 1 этаж: 101–110 (10).
- 2 этаж: 201–216 (16).
- 3 этаж: 301–317 (17).

Сканирование открывает `/chat?qr=<случайный идентификатор>`. На телефоне это полноэкранный чат с пузырями сообщений, закреплённым полем ввода, фото и подтверждением, по образцу привычного мобильного мессенджера. Никакой установки приложения не нужно. Две палитры («Сад», «Ночь») сохраняются на устройстве. Анимации уважают `prefers-reduced-motion`.

Готовые изображения можно также получить командой:

```bash
.venv/bin/python scripts/export_qr.py --url http://localhost:3001 --output artifacts/qr
```

Скрипт использует локально созданный пароль администратора из `.local-credentials` или `ADMIN_PASSWORD`, не печатает его, сохраняет PNG по этажам и архив `artifacts/upk-qr-codes.zip`.

## Возможности

- Заявки с явным подтверждением, категорией, местом и фотографией JPEG/PNG/WebP до 8 МБ. Изображения проверяются, уменьшаются, перекодируются в JPEG без EXIF и хранятся в БД.
- Уникальные номера, идемпотентная отправка и безопасные ссылки с 256-битным токеном. В БД хранится SHA-256 токена. При повторе той же отправки сервер возвращает прежнюю заявку.
- Публичные комментарии и история. Заявитель отвечает сотруднику в карточке. Внутренние заметки видны только сотрудникам. «Мои обращения» хранит ссылки только на этом устройстве; при очистке хранилища они исчезнут. Сохраните адрес важной заявки отдельно.
- Авторизация с Argon2id и 12-часовой HttpOnly cookie-сессией. Сервер проверяет роли на каждом защищённом маршруте. Сотрудник не управляет пользователями, помещениями и QR.
- Поиск по номеру и описанию, фильтры по статусу, категории, кабинету и датам, назначения исполнителей, все семь статусов, обязательная причина решения/отклонения. Конфликт одновременного редактирования возвращает 409.
- Реальная аналитика: всего, открытые, решённые, срочные, категории, кабинеты, типы ответов помощника и среднее время решения.
- Экспорт CSV с защитой от формул, управление сотрудниками и категориями, журнал административных действий.

## Архитектура и данные

```text
Мобильный/настольный браузер
  React + Vite
       │ /api (cookie или персональный tracking-токен)
  Python FastAPI
       ├── SQLite: заявки, роли, история, фото, знания, QR
       └── DeepSeek API: только сервер, ключ из .env
```

Разработка: Vite `5173` проксирует `/api` на FastAPI `3001`. Production: `npm run build`, затем `npm start`. FastAPI отдаёт готовый `dist` и API с одного порта 3001. Для QR задайте соответствующий публичный адрес. В production нужен HTTPS, `COOKIE_SECURE=true`, закрытый доступ к серверным файлам, резервное копирование `.data/upk.sqlite` (вместе с WAL при работе) и собственные учётные записи.

Модели и связи описаны в [docs/architecture.md](docs/architecture.md). Карта соответствия ТЗ и тестов — [docs/acceptance.md](docs/acceptance.md). Сценарий демонстрации и текст короткой презентации — [docs/demo.md](docs/demo.md).

Схема базы и каталоги создаются автоматически. `DB_PATH` позволяет выбрать отдельный файл. База SQLite, `.env`, пароли и тестовые результаты исключены из Git. Секрет для tracking-ссылок создаётся в БД: сохраняйте его при резервном копировании, иначе повторная отправка старого idempotency-key не сможет восстановить ту же ссылку.

## Проверки

```bash
npm test
npm run build
npm run test:e2e
```

Pytest проверяет API, все примеры из приложения А, права, приватность, фото, повторную отправку, QR и отказоустойчивость DeepSeek через подменённый HTTP-сервис. Playwright выполняет сквозной сценарий с фото, назначением и решением, проверяет мобильный чат, темы и отсутствие горизонтального скролла. Браузер Chromium ожидается по `/usr/bin/chromium` — измените `executablePath` в `playwright.config.js` под свою систему или используйте установленный Playwright-браузер. E2E использует отдельную БД и порт 3002.

## Известные ограничения

Ключ DeepSeek настроен в серверном `.env`; живой вызов модели проверен 6 ноября 2026: HTTP 200, provider=deepseek. Фото модель не распознаёт. Опциональные Telegram/email-уведомления, карта, похожие заявки и оценка удовлетворённости не входят в эту версию. Локальная классификация ограничена правилами и может попросить уточнение для нестандартной фразы. При подключении DeepSeek текст диалога уходит внешнему провайдеру. После изменения системного промпта следует проверять ответы на типовых ситуациях колледжа.

SQLite и хранение фото в БД подходят для MVP и одного сервера. Для масштабного внедрения потребуются PostgreSQL, отдельное файловое хранилище, общий rate limiter, политика хранения данных и эксплуатационный мониторинг. Встроенное ограничение частоты действует в одном процессе. Проект подготовлен локально, удалённый Git-репозиторий и публичный хостинг пока не созданы.
